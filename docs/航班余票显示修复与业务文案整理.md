# 航班余票显示修复与业务文案整理

日期：2026-11-20。

## 余票问题的原因

搜索查询原先同时返回 `h.*` 中的旧 `number` 字段和别名同为 `number` 的舱位汇总。JDBC 行映射保留第一个同名字段，旧缓存值 0 覆盖了实际舱位余票，页面因此将有票航班显示为售罄。

本机数据库只读核查发现，未来 14280 个航班的旧缓存为 0，而对应舱位仍有余票；舱位库存及座位一致性检查均为 0 个异常。没有通过增加或重置库存修复此问题。

## 修复内容

- 查询以独立字段取得舱位汇总，映射后显式设置 `number`，避免同名字段覆盖。
- 同行人数只影响可选舱位和报价，不再将不足人数的舱位库存误记为空。
- 返回明确的预订状态，区分可预订、售罄、同行余票不足、未开售、截止预订、已起飞、停售、取消和库存暂不可用。
- 日期价格与“仅看可预订”共用销售窗口和舱位条件。

## 业务文案

门户、订单详情、行程卡、日历和乘机人管理使用正式业务表达。费用名称统一为税费、燃油附加费和选座服务。订单确认不承诺外部资金扣款。

V11 迁移整理班期编号、票价规则和航司介绍中的旧说明，仅处理匹配旧模板特征的数据。内部主键、航线标识、金额、费率、行李额度、库存和订单关联不变。

历史订单快照保持原样；展示层对已知旧费用标签与说明进行兼容转换，退款计算继续使用购票时保存的数值规则。自定义的旅客姓名和审核原因不做全局文本替换。
