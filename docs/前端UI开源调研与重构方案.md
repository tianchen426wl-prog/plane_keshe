# 航空售票系统：开源 UI 调研与重构方案

调研日期：2026-11-20。适用项目：plane_keshe，Vue 2 + Element UI 的 portal/admin 双前端。

## 1. 推荐结论

门户采用“轻量航空品牌 + 搜索优先 + 航班卡片 + 分步确认”，后台采用“浅色工作区 + 分组侧栏 + 标准筛选表格 + 详情侧栏”。两端共享色彩、字号、状态和间距，针对购票与管理使用不同的信息密度。

本轮沿用现有 Vue 2、Element UI、Vuex、Router 和 API 封装，以组件重构与主题规范落地；Vue 3 迁移单列后续工作。Vue 2 已于 2023-12-31 结束官方维护，保留旧栈是当前课程项目控制改动范围的选择，不作为长期产品路线。[Vue 官方说明](https://v2.vuejs.org/eol/)

本次交付为方案及独立交互示意，不覆盖现有业务页面，不改数据库。示意页面在 `ui-redesign-preview.html`，所有展示数字均为示例，按钮不会创建订单。

## 3. 当前 UI 的具体问题

依据当前 App.vue、Home.vue、FlightSearch.vue、MyOrders.vue、AdminLayout.vue 及既有浏览器截图：

1. 门户顶栏为大面积默认蓝，登录后导航项增多；个人中心、我的订单、退出与主要购票入口争夺空间。
2. 首页 500px 轮播先占首屏，搜索区靠负 margin 叠放，缺少明确的搜索主任务层级。
3. 面向旅客的航班结果使用密集后台表格，价格、航班和购买操作横向分散；窄屏依赖横向滚动。
4. 选择舱位、数量、占位倒计时和确认购买集中在高弹窗内，正文与操作区距离较远。
5. 公司、资讯、登录及订单页面仍有不同的卡片边框、阴影、标题和空状态风格。
6. 后台侧栏平铺，筛选栏和操作区位置不统一；长订单号、时间、价格和多个行按钮造成视觉拥挤。
7. 订单日志虽已可查，但需要更清晰的“业务操作/状态变化”解释及详情信息层级。

另发现 UI 改造时应修复的行为：portal/App.vue 的退出仍直接清理本地状态，应接入已有 logout action，避免绕过服务端撤销；其双重菜单事件也应合并。此项是后续实施待办，本轮未改动。

## 4. 统一视觉规范

设计方向名暂定“云际航空 / Air Ticket”，用于呈现设计意图；对外名称仍可保留课程题目“航空售票管理系统”。不冒充真实航司或出票平台。

| 设计项 | 建议值/规则 |
|---|---|
| 主色 | #1D4ED8；主按钮、选中态、关键导航 |
| 品牌深色 | #0F2747；标题、页眉品牌区 |
| 背景/表面 | #F5F7FB / #FFFFFF；避免所有容器都有阴影 |
| 正文/次级文字 | #172B4D / #52637A；更浅灰仅用于装饰，不承载关键内容 |
| 边界 | #DEE5EF；1px 轻分隔，表格优先水平线 |
| 成功/警告/危险 | #15803D / #B45309 / #B91C1C，搭配明确文字和浅色背景 |
| 价格 | 蓝色或深色数字突出；红色主要留给错误、危险操作和临近到期 |
| 字体 | 本地系统字体：PingFang SC、Microsoft YaHei、sans-serif；不依赖外网字体 |
| 字号 | 页面标题 28/32，区块标题 20，正文 14/16，说明 12；订单金额 26/30 |
| 间距 | 4、8、12、16、24、32、48；页面通常 24px 内边距 |
| 圆角 | 控件 8，卡片 12，大容器 16；不把所有形状都做胶囊 |
| 控件 | 门户输入/主操作 44～48px；后台常规控件 36～40px |
| 内容宽度 | 门户最大 1200px；后台自适应，阅读详情最大 960px |
| 动效 | 120～200ms，仅用于展开/切换；尊重减少动态效果偏好 |
| 图标 | 使用项目现有图标或统一的本地 SVG 图标集；重要操作有文字，不混用多套风格 |

将规范落实为两端同名 CSS 变量及 Element UI 覆盖层。前台可使用 14px 圆角与较大留白，后台保持紧凑；变量共享不等于所有页面布局相同。

## 5. 门户信息架构与逐页方案

### 5.1 导航与首页

桌面导航：品牌｜订机票｜航空公司｜出行资讯；右侧“我的订单”与账户菜单。账户菜单收纳个人中心、修改密码、退出。手机使用可展开导航，不把所有条目压入单行。

首页首屏：简短航空主题标题 + 搜索卡。搜索卡只放当前支持的单程、出发地、目的地、日期；交换城市是本地操作。数量仍在选舱确认时输入，避免搜索人数与实际库存语义不一致。

第二屏：当前真实可售航班入口/航线；再展示航空公司和 3 条最新资讯。接口没有“热度”字段，标题使用“可选航线”“航空公司”，不把列表前几条包装成“热门排行”。

减少自动播放轮播，优先使用已有本地图片的单幅品牌区或轻插画。首屏在 1366×768 下能看到完整搜索区及主按钮。

### 5.2 航班结果页

结构：顶部可编辑查询摘要 → 结果数 → 航班卡片列表 → 分页。桌面筛选可以放左侧，窄屏收纳为筛选抽屉。

单张 FlightCard 的主次顺序：

- 航司及航班号；起飞时间为主视觉。
- 出发城市 → 目的城市、起飞日期、飞行时长和乘机地点。
- 右侧“¥800 起/张”和选择舱位按钮；下方显示真实余票及可售状态。
- 展开舱位后展示经济/商务/头等三个选项：名称、锁定前单价、余票、数量及主操作。

**数据边界**：现有字段没有结构化到达时间、机场代码、中转次数、免费行李、餐食、座椅间距及舱位权益。第一阶段不展示这些断言；duration 即使能解析也不能静默当作正式到达时刻。原型示例只呈现起飞时间与现有飞行时长。

价格/起飞时间/航司全量筛选和排序需要后端查询支持，不得只排序当前 20 条后声称全局最低价。第一阶段仅提供已有城市/日期分页；扩展筛选先补白名单 API 与测试。日期快捷条必须改变查询日期后重新请求，不能填造当天价格。

### 5.3 选舱与确认

推荐路由：`/flight` 选舱 → `/booking/:holdId` 确认 → `/booking/result/:holdId` 结果。状态可以由服务端占位恢复，不依赖页面内存。

桌面确认页采用主内容+320px订单摘要；手机垂直排列并保留底部主按钮。可使用 el-drawer 承载轻量选舱，但占位后的确认保留可刷新恢复的独立页。

确认页包含：航班、舱位、数量、占位单价、总额、服务端到期时间、规则摘要、明确“确认模拟支付”。数量 1～5、最多 3 个未完成占位等约束与后端一致。

交互：选择舱位→点击锁定才创建占位；单纯展开卡片不扣库存。创建后固定该次价格和数量，调整需明确取消并重新占位；确认失败区分过期、售罄、停售、未登录、网络不确定状态。网络超时后先查询已有占位/订单再重试，沿用 requestId。

TTL 以 expireTime 计算；建议返回 serverTime 校正客户端时钟。剩余 <3 分钟提示加重，<1 分钟使用警告并有文字。按钮清楚说明“关闭保留占位”和“取消并释放”，不能仅靠关闭图标表达。

### 5.4 我的订单与详情

列表改订单卡片：顶部状态+订单号，中部航线/日期/舱位/数量，右侧总价，底部主操作。待支付、已购票、退订中、已退订保持现有业务状态。

详情使用分组卡片：行程快照、费用、订单状态、退订说明、时间线。退款拒绝后订单恢复已购票，应在卡片中保留“上次退订未通过”及原因，不增加不存在的终态。需补用户可访问的审核结果/详情 API。

现有 jpdd/create 只返回成功状态，结果页通过 holdId 关联已有订单；建议响应直接返回 orderId/orderNo，并维持幂等。历史快照缺失显示“历史记录”，不能展示伪造权益。

### 5.5 其他门户页面

| 页面 | 方案 |
|---|---|
| 登录/注册 | 桌面双栏，左侧轻品牌说明、右侧表单；手机单栏；允许粘贴密码，错误紧邻字段 |
| 个人中心 | 左侧账户导航，右侧资料/安全两块；改密后明确重新登录 |
| 公司列表/详情 | 标识、名称、简介和联系方式；照片统一比例，不能把商标拉伸成旅游封面 |
| 资讯列表/详情 | 阅读型页面，正文最大 760px、行高 1.7；列表摘要 2～3 行；保留纯文本安全渲染 |
| 空/错/加载 | 页面骨架、查询无结果、登录失效、接口失败分别呈现；保留查询条件和明确恢复按钮 |

## 6. 后台工作台方案

### 6.1 布局与导航

侧栏 232px，折叠 64px，顶栏 60px。内容区浅灰底，左对齐页面标题、说明和面包屑；主操作位于标题右侧。内容不足时不为了填满屏幕放大卡片。

导航分组：工作台；基础资料（用户、公司、航班）；交易管理（订单、退订）；内容管理（资讯）；系统设置（菜单、管理员）。分组由当前已有菜单在前端映射，不要求立即改变数据库结构；无权限子项不渲染，空组隐藏。

默认不堆多标签页、全屏、语言切换、主题切换等工具。先保证导航状态、返回上下文和长表格可用；后台长期深色主题为后续选项。

### 6.2 页面模板

统一 PageHeader → FilterBar → TableToolbar → DataTable → Pagination。筛选不超过 3 个常用条件，更多条件折叠；重置同时回到第一页。

表格保留关键 6～8 列：编号/名称、核心业务信息、状态、时间及操作；长订单号可复制或悬停完整显示，金额右对齐。详情移入 Drawer，减少横向滚动；只有真正有批量接口的页面才显示批量按钮。

### 6.3 核心页面

| 页面 | 改造 |
|---|---|
| 工作台 | 当前用户数、航班数、订单数、待审核数；明确统计口径；用真实待办引导至退订列表 |
| 航班 | 筛选区+航班表；列展示航班号、航线、起飞、可售状态、余票；编辑与舱位管理侧栏分离 |
| 舱位 | 三舱卡片/紧凑表；余票只读、容量可调整、价格可编辑；下调失败显示后端原因 |
| 订单 | 状态标签、金额、用户脱敏信息；详情侧栏含快照、日志、复制订单号；无手改状态按钮 |
| 退订 | 待审核队列优先，详情与审核意见并排；通过/拒绝均二次确认；重复请求期间禁用按钮 |
| 管理员 | 0/1 角色文案与后端一致；权限按分组勾选，系统权限仅超管；保护最后一个超管 |
| 公司/资讯 | 使用同一 CRUD 表单模板；详情和编辑明确区分；已有历史引用时采用停用 |

待审核数徽标只有拥有退订权限才拉取。当前没有趋势统计接口，工作台暂不画虚构折线图；若后续增加，必须给出日期范围、统计口径和空值处理。

## 7. 组件与工程落点

新增两端同名设计变量文件、基础 reset、Element UI 覆盖层；CSS 使用 portal/admin 根作用域，避免 portal 全局 `.el-menu` 覆盖后台。先用 CSS 变量，只有确需编译 Element 主题时才引入匹配现有构建工具的 Sass 依赖。

门户组件：PortalHeader、SearchPanel、FlightCard、CabinSelector、BookingSummary、HoldCountdown、OrderCard、StatusBadge、FeedbackState。

后台组件：AdminShell、PageHeader、FilterBar、TableToolbar、StatusBadge、DetailDrawer、AuditTimeline。表格不做过度抽象：通用外壳统一，航班/退款等业务列保持清晰。

| 现有文件 | 改造方向 |
|---|---|
| portal/App.vue | 新导航/账户菜单/小屏菜单；退出改用已有认证 action |
| portal/views/Home.vue | 搜索优先布局，移除负 margin 耦合，降低轮播依赖 |
| portal/views/FlightSearch.vue | 表格拆 FlightCard+CabinSelector；保留查询参数和分页 |
| portal/views/MyOrders.vue | 订单卡片和详情；保留状态恢复及接口幂等 |
| portal/router/index.js | 新确认/结果路由，携带 holdId，刷新恢复 |
| portal/api/jpdd.js | 新详情与明确返回契约；错误信息保持统一 |
| admin/views/layout/AdminLayout.vue | 分组侧栏、面包屑、标准页头 |
| admin/views/*Manage.vue | 统一筛选、表格、详情侧栏和表单 |
| scripts/browser-smoke.cjs | 使用 data-testid/语义标签替换依赖旧 CSS 和固定列的定位 |

建议先补 stable test IDs，再替换 DOM，防止自动化测试随着视觉布局失效。复用现有 Axios、登录凭据及后端权限；UI 不能自行把失败状态包装成功。

## 8. 数据与 API 改造界线

| 功能 | 第一阶段现状 | 如启用需补充 |
|---|---|---|
| 搜索/航班卡片 | 已有城市、日期、航班号、价格、余票、时长等 | 无需改库；保持现有分页 |
| 当前用户占位恢复 | 已有 myHolds；列表只含有效占位 | 受归属保护的 hold 详情，能够返回已转订单或过期状态 |
| 结果页 | create 仅成功/失败 | 返回已有/新建 orderId、orderNo；按 holdId 查询本人结果 |

| 全量排序与高级筛选 | 当前 API 未提供 | 服务端白名单排序/条件及对应 count；新增索引按执行计划决定 |
| 价格日历、往返、中转、座位图 | 没有模型 | 本轮不提供；后续作为业务扩展单独设计 |
| 订单及业绩趋势 | 当前只有总数类数据 | 时间区间统计接口与权限，再决定是否引入图表依赖 |

## 9. 实施批次与验收

建议 2 人约 7～10 个工作日，取决于可投入时间；这是估算，不是课程截止日期。

1. 1 天：确认视觉方向，建立变量、导航、按钮/表单/状态规范，补测试定位。
2. 2～3 天：首页、搜索、选舱卡片；宽屏与窄屏同步实现。
3. 1～2 天：确认/结果页、订单卡片与详情；补最小 API，不改变库存规则。
4. 2 天：后台布局、列表模板、航班/退款/订单侧栏。
5. 1～2 天：辅助页面、完整回归、截图、开源来源记录与课程报告配图。

验收：

- 1440、1366、768、390px 宽度无页面整体横向溢出；关键主按钮始终可达。
- 1366×768 下首屏可直接搜索；390px 可独立完成选舱和确认，不依赖悬停。
- 键盘可操作表单、菜单、舱位与抽屉；关闭后焦点回到触发控件；颜色不是唯一状态标识。
- 正文对比度目标≥4.5:1，大字≥3:1；在真实背景和 disabled 状态区分中逐项测量，不能仅凭色板宣称合格。
- 搜索、占位、刷新恢复、重复确认、退出、退订拒绝/通过、越权、断网/过期路径有端到端记录。
- 现有 18 项后端集成测试继续通过；两个前端 build 通过。
- 不出现虚构航班、伪造行李权益、无接口支撑的筛选或假统计。
- 新增图片优先本地、明确授权，首屏资源量与改造前记录比较；减少入口包体，不凭感觉宣称加载提速。

## 10. 原型说明与设计来源边界

配套 HTML 提供首页、航班结果、确认和后台四个可切换示意，展示布局、主次层级、配色与选舱金额变化。示例使用 COURSE101 等课程标识，全部标明示例数据；无网络请求，不绑定数据库。它不是已完成的 Vue 页面，也没有证明全部可访问性或业务接口已经实现。

本项目的具体色值、尺寸、模块分组、路由建议、交互规则和实施排期是本次针对现有项目制定的设计方案。开源项目提供模式参考；不宣称复刻了未实际浏览验收的全部演示页面。
