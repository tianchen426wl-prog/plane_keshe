# 第一批体验优化交付说明

日期：2026-11-20。对应《体验功能扩展调研与建议》的第一批实施范围。

## 已实现的功能

### 搜索人数与筛选

- 首页和航班页可选择 1～5 位成人，人数传到查询、预订与报价。
- 新增舱位、起飞时段、整单预算、每人托运行李额度和“仅看可预订”筛选。
- 增加抵达时间、飞行时长排序；筛选与排序在后端完成后再分页。
- 日期价格与搜索共用条件，日期条展示同行人数对应的合计起价；航班卡同时显示单张价格和多人合计。
- 延续已有城市别名、机场名称/代码查询和停用旧课程班期的隐藏规则。
- 默认保留全部航班的存在性展示，售罄航班不可购买；勾选“仅看可预订”后按同行人数和销售状态筛选。
- 浏览器前进/后退同步恢复搜索条件；异步请求使用序号避免较旧响应覆盖新结果。

预算指基础运价与必付费用的整单金额，不含用户另选的收费座位。页面已注明口径，最终费用仍以报价与占位为准。

### AI 推荐衔接预订

- 候选跳转保留航班 ID、人数、日期和总预算。
- 航班页加载指定候选并打开选舱；预订前重新读取航班状态和可用舱位。
- 登录跳转保留目标航班与人数。
- 本轮不改变模型支持范围，仍为国内成人直飞单程。

### 常用成人乘机人

- 个人中心新增“常用乘机人”，支持添加、编辑、删除，最多 20 位。
- 预订时可多选档案，依次填入旅客姓名，也可手动填写和修改。
- 本期仅保存演示姓名，不新增证件采集。
- 新增 `/api/user/passengers` 及按 ID 编辑、删除接口，账户身份从服务端登录态取得。
- 新增 V10 `passenger_profile` 表，按用户隔离；档案修改不会回写已购订单。

### 三步预订与手机端布局

- 将预订弹窗划分为“选择舱位—旅客与座位—核对费用”。
- 选舱默认继承搜索人数；余票不足以满足同行人数的舱位不能选择。
- 返回上一步保留当前输入；修改姓名、座位或人数后原报价失效。
- 手机端使用全宽布局、单行步骤标题与底部操作区；保留免费自动分配和费用明细。

### 完整订单详情与演示行程卡

- “我的订单”新增“行程与订单详情”入口。
- 展示航班、机场/航站楼、出发/抵达、乘机人脱敏姓名、座位、行李、费用、业务进度和退款审核理由。
- 新订单保存更完整的购票时航班快照，同时分开展示当前航班信息；历史订单缺少的字段显示未提供。
- 提供打印演示行程卡与 ICS 日历导出，使用稳定事件 ID、UTC 时间、文本转义和 UTF-8 折行。
- 已退订、退订中和已取消航班不能导出有效行程日历。
- 行程卡明确标识课程演示用途，不作为真实客票或报销凭证。

## 数据库与构建

- 保留工作区已有的 V9 航线扩充迁移，本轮新增 V10；没有改写 V1～V9。
- Flyway 启动时升级；默认数据库版本为 V10。
- 旧库接管范围扩展至 V10，增加 V10 常用乘机人表存在性检查。
- POM 增加可选的 `airticket.build-directory`，默认仍为 `target`。当默认 JAR 被占用时，可将构建输出到另一个项目内目录。
- 本机已将可执行包交付到 `air-ticket-server/target/air-ticket-server-1.0.0-experience.jar`。启动和数据库维护脚本会从默认包与该备用包中选择最新的有效可执行包，跳过缺少启动清单的普通 JAR；不需要覆盖当前被占用的文件。

```powershell
. ./scripts/activate.ps1
mvn.cmd -f air-ticket-server/pom.xml verify
npm.cmd run build --prefix air-ticket-web/portal

# 默认构建目录被占用时的可选输出方式
mvn.cmd -f air-ticket-server/pom.xml '-Dairticket.build-directory=D:/keshe/plane_keshe/tmp/experience-server-target' -DskipTests package
```

正常启动入口保持 `start_backend.ps1` 和 `start_frontend.ps1`。前端服务读取 `portal/dist`，本轮已重新构建该目录。后端运行中的进程需要重新加载新包后才能提供新增 API，数据库迁移随新后端启动执行。

## 验证结果与边界

- 最终后端回归：56 项测试、0 失败、0 错误、0 跳过。包括已有购票/退款测试、新增筛选与权限测试，以及 V4/V8/V9/V10 接管、空库和重复启动等迁移测试。
- 后端测试在 `air_ticket_test` 与测试自行分配的 `air_ticket_boot_it_*` 库运行。
- 门户正式构建成功。构建仍有供应商代码和原有横幅图片体积警告，不影响编译通过。
- 浏览器回归使用正式 `dist` 资源与明确的 API 测试数据，共 8 组检查通过，无页面脚本错误。它验证界面行为，不等同于真实后端端到端下单；业务与数据校验由上述集成测试覆盖。
- 日历专项测试通过：北京时间转换、UTF-8 折行、文本注入转义及无效/已退订行程校验。
- 独立目录可执行包构建成功，已核对启动清单、V10 迁移与乘机人 API 类。通过更新后的维护脚本对 `air_ticket_test` 运行升级检查成功：10 个迁移校验通过，版本 V10 无需重复迁移，执行后退出且未启动 HTTP 或航班任务。
- 本轮没有主动停止主库服务，也没有向主库创建测试订单。
